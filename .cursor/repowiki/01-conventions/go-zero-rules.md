# go-zero 开发规范与 goctl 生成规则

> 版本：v1.1 | 更新：2026-08-06 | 来源：`.cursor/rules/tjxt-project.mdc`、`.workbuddy/memory/MEMORY.md`、本次模块拆分重构（每 api/rpc 独立 module）

## 核心原则：生成优先，手写最小化

> **只手写三类文件**：
> 1. `internal/logic/*.go` - 业务逻辑
> 2. `internal/model/*model.go` - Custom Model 扩展方法（不含 `*_gen.go`）
> 3. 业务扩展文件（如 `solution.go`、常量定义 `consts.go`、`vars.go`）
>
> **禁止手写**：handler、types、routes、pb、server 骨架、config 骨架

---

## 开发标准流程（严格按序）

```
1. 设计 DB 表结构
         │
         ▼
2. 写入 sql/ddl/tj_<domain>.sql (纯 DDL)
         │
         ▼
3. goctl model 生成 Model 层
         │
         ▼
4. 设计 Proto 文件 (apps/<svc>/rpc/<svc>.proto)
         │
         ▼
5. goctl rpc 生成 RPC 骨架 (pb/server/client/logic/svc/config)
         │
         ▼
6. 设计 API 文件 (apps/<svc>/api/<svc>.api)
         │
         ▼
7. goctl api 生成 API 骨架 (handler/logic/types/routes)
         │
         ▼
8. 手写 Logic 实现业务
         │
         ▼
9. 构建测试
```

## 已验证的标准 goctl 命令

### API 生成
```bash
cd apps/<svc>/api
goctl api go --api <svc>.api --dir . --style gozero
```
- 输出目录 = `.api` 所在目录
- 不覆盖：`handler/`、`logic/`、`internal/svc/`、`internal/config/`
- 仅刷新：`internal/types/`、`internal/handler/routes.go`

### RPC 生成
```bash
cd apps/<svc>/rpc
goctl rpc protoc <svc>.proto \
  --go_out=. --go-grpc_out=. --zrpc_out=. \
  --style gozero --client=true
```
- `-m` 标志可生成 logic 模板（首次用）
- 不覆盖：`internal/logic/`、`internal/svc/`、`internal/config/`
- 仅刷新：`pb/`、`internal/server/`、client 代码

### Model 生成（从 DDL）
```bash
goctl model mysql ddl \
  -src sql/ddl/tj_<domain>.sql \
  -dir apps/<svc>/rpc/internal/model \
  -cache --style gozero
```
- `-cache` 启用 Redis 缓存
- 生成：`*_model.go`（可编辑）、`*_model_gen.go`（勿动）、`vars.go`
- 已存在 Model 时：**只在 `*_model.go` 扩展方法，不要重新生成覆盖**

## 命名与结构约定

| 项目 | 规范 | 示例 |
|------|------|------|
| 模块路径 | `module tjxt/apps/<svc>/api` 与 `module tjxt/apps/<svc>/rpc` | `module tjxt/apps/auth/api`、`module tjxt/apps/auth/rpc` |
| 目录布局 | api 与 rpc 各自独立 `go.mod` | `apps/<svc>/api/go.mod`、`apps/<svc>/rpc/go.mod` 分别管理依赖 |
| 目录命名 | gozero 风格（小驼峰，无下划线） | `internal/logic`, `userCoupon` |
| 文件命名 | 小驼峰 | `userCouponLogic.go`, `couponModel.go` |
| 包名 | 目录名一致 | `package logic` |
| Proto 服务名 | `<Svc>Service` | `service AuthService` |
| API 服务名 | `<svc>.api` | `auth.api` |

## Model 扩展模式

```go
// apps/auth/rpc/internal/model/usermodel.go (手写，可编辑)
package model

import (
    "context"
    "github.com/zeromicro/go-zero/core/stores/sqlx"
)

type UserModel interface {
    UserModelGen    // 嵌入生成的接口
    FindByPhone(ctx context.Context, phone string) (*User, error)
    FindByEmail(ctx context.Context, email string) (*User, error)
}

func (m *defaultUserModel) FindByPhone(ctx context.Context, phone string) (*User, error) {
    var resp User
    query := "select * from `user` where `phone` = ? limit 1"
    err := m.conn.QueryRowCtx(ctx, &resp, query, phone)
    return &resp, err
}
```

## 常见错误与规避

| 错误现象 | 原因 | 规避 |
|----------|------|------|
| 手改 `*_gen.go` 被覆盖 | 重新生成 model | 只在 `*_model.go` 扩展 |
| `.api` 里用 `any` 类型报错 | goctl 不支持 `any` | 用 `interface{}` 代替 |
| handler 里直接返回 JSON | 违反统一响应规范 | 用 `result.Write(w, r, data, err)` |
| 跨服务 import internal 包 | 破坏模块边界 | 只能调用对方 RPC client |
| RPC client 未生成 | 忘加 `--client=true` | 命令固定带上 |
| 配置文件不生效 | yaml 字段名与 struct tag 不匹配 | 对照 `config.go` 检查 |

## 已注入的可观测性配置（勿删）

每个服务的 `apps/<svc>/{api,rpc}/etc/*.yaml` 已由脚本注入三块可观测性配置，**禁止删除或改坏字段**：

```yaml
Telemetry:                 # 链路追踪：go-zero 自动 StartAgent，推 OTLP 到 127.0.0.1:4318
  Name: <svc>
  Endpoint: 127.0.0.1:4318
  Sampler: 1.0
  Batcher: otlphttp

Prometheus:               # 指标：各自暴露 /metrics，由 otel-collector 抓取后聚合
  Host: 0.0.0.0
  Port: <唯一>            # RPC 9101-9113 / API 9201-9213
  Path: /metrics

Log:                      # 日志：写 JSON 文件，由 collector filelog 采集进 Loki
  Mode: file
  Encoding: json
  Path: logs/<svc>        # 相对仓库根；服务须从仓库根启动
  Level: info
```

若需重生成骨架（`goctl api go` / `goctl rpc protoc`），这些配置**不会被覆盖**（goctl 只刷新 types/routes/pb/server），可放心重生成。完整说明见 [可观测性文档](../04-infra/observability.md)。

## Makefile 常用目标速查

| 目标 | 作用 |
|------|------|
| `make api` | 全量重新生成所有 API 骨架 |
| `make rpc` | 全量重新生成所有 RPC 骨架 |
| `make model` | 从 DDL 生成所有 Model |
| `make generate` | `api + rpc` 一键生成 |
| `make build` | 构建全部 26 个二进制到 `bin/`（13 服务 × {api,rpc}） |
| `make test` | 全模块 `go test ./...` |
| `make fmt` | 全模块 `go fmt ./...` |
| `make verify` | 校验 `.api`/`.proto`/`internal/` 目录齐全 |
| `make run-<svc>` | 前台启动单个 API 服务 |
| `make run-<svc>-rpc` | 前台启动单个 RPC 服务 |
| `make run-all` | 后台并行启动所有 API |
| `make run-all-rpc` | 后台并行启动所有 RPC |
| `make docker-up` | 启动 MySQL/Redis/RabbitMQ/etcd |
| `make tidy` | 全模块 `go mod tidy` |
